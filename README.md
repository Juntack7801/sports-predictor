# sports-predictor

기획서 기반으로 시작한 파이프라인 프로젝트입니다. (기획서 파일 자체는 이 저장소에는 포함되어 있지 않습니다.)
1단계로 **MLB collector**만 구현되어 있음 (공식 API 기반, 검증 완료).

## 실행 방법

```bash
cd sports-predictor
pip install -r requirements.txt

# 오늘 날짜 기준 수집
python collectors/mlb_collector.py

# 특정 날짜 지정
python collectors/mlb_collector.py --date 2026-07-27

# DB 파일 경로 지정
python collectors/mlb_collector.py --date 2026-07-27 --db sports.db
```

실행하면 `sports.db` (SQLite)에 다음 테이블이 채워진다:
- `teams`: 해당 경기에 등장한 팀
- `games`: 경기 일정/스코어/구장/시리즈 상황
- `probable_pitchers`: 홈/원정 선발투수의 최근 5경기 ERA/WHIP(자체 계산), 시즌 ERA/WHIP, 휴식일수

## 확인된 사항 / 남은 작업

- MLB collector, 팀 스탯 수집, feature_builder, predictor_v1, API 서버, 웹 화면까지 **전체 파이프라인이 mock 데이터로 엔드투엔드 테스트 완료** (KBO/NPB 포함, 리그별 필터링까지 확인함).
- **실제 MLB Stats API 호출은 이 환경의 네트워크 제한 때문에 직접 검증하지 못했다.**
  집 컴퓨터 등 외부 네트워크가 열린 환경에서 최근 실제 경기가 있었던 날짜로 먼저 한 번 돌려보고,
  아래 항목이 예상과 다르면 파싱 부분을 조정할 것:
  - `seriesStatus` 필드명 (result/shortName/wins/losses 등 시즌 중 실제 응답으로 재확인)
  - `probablePitcher`가 아직 발표 전인 경기의 응답 형태
  - `/standings` 응답의 `records.splitRecords` 타입명(home/away/lastTen)이 실제로 맞는지
- **KBO/NPB collector는 스크래핑 기반이라 이 환경에서 실제 사이트로 테스트하지 못했다.**
  각 파일 맨 위 주석에 "이 부분이 안 맞으면 여기를 고치세요" 안내가 있음. 실제로 돌려서
  "경기를 찾지 못했습니다" 경고가 뜨면, 브라우저에서 F12(개발자도구) 눌러서 실제 페이지의
  class명/표 순서를 확인하고 코드 상단 `SELECTOR_*` / `COLUMN_INDEX` 값만 고치면 됨.
- **오버/언더 라인은 이제 배트맨(betman.co.kr) 실제 배당 라인을 우선 사용한다.**
  `betman_odds_collector.py`가 오늘 경기의 실제 언더/오버 라인을 가져와 저장하면,
  예측 계산 시 그 라인을 기준으로 오버/언더 확률을 계산하고 화면에도 그 실제 라인을 보여준다.
  배당 라인을 못 가져왔거나 팀명 매칭에 실패한 경기는 예전처럼 자체 계산한 라인(0.5 단위 반올림)으로 대체됨.
  - **이것도 스크래핑이라 이 환경에서 실제 사이트로 테스트하지 못했다.** `collectors/betman_odds_collector.py`
    맨 위 주석 참고해서 SELECTOR_* 값을 실제 페이지에 맞게 조정할 것.
  - 배트맨은 한글 팀명, 우리 DB는 MLB=영문/NPB=일본어라서 `collectors/team_name_map.py`에
    변환표를 만들어뒀음. 실제로 돌려서 매칭 안 되는 팀이 있으면 이 파일에 그 팀만 추가하면 됨
    (KBO는 어차피 한글이라 매핑 없이도 대부분 매칭됨).
- **화면 이름을 "배트 서포터"로 변경**하고, 헤더를 두 줄(앱 이름 + "오늘의 경기 예측")로 나눠 가시성을 높였다.
- **투수 방어율(ERA), 팀 시즌 승률/최근10경기 승률을 카드에 표시**한다. 실제로 수집된 값만 보여주고,
  값이 없으면 절대로 임의의 숫자를 지어내지 않고 "정보 없음"이라고 정직하게 표시한다.
- **오버/언더 확률이 배트맨 실제 배당 라인 기준인지, 자체 계산 라인인지를 화면에 초록/회색 태그로 구분 표시**한다
  ("배트맨 실배당" / "자체 계산") — 어떤 값이 실제 사실이고 어떤 값이 우리 모델의 추정인지 항상 명확히 구분하기 위함.
- **화면에 날짜 선택 칸을 추가**했다. 오늘뿐 아니라 과거 날짜(예: 어제)도 골라서 볼 수 있고,
  이미 끝난 경기는 실제 스코어와 함께 "승패 적중" / "승패 실패" 뱃지가 표시된다.
  (오버/언더도 마찬가지로 적중 여부를 작게 표시)
- **`check_accuracy.py`**가 새로 생겼다 — 끝난 경기의 실제 스코어와 예측을 비교해서
  `accuracy_log` 테이블에 적중/실패를 기록한다. `daily_refresh.bat`에 자동으로 포함되어
  매일 실행될 때 전날 결과를 확인한다. 수동으로도 실행 가능:
  ```
  python check_accuracy.py --date 2026-07-31
  ```
- 화면 맨 위에 **"베팅 프로그램이 아니라 참고용 예측 도우미"라는 안내 문구**를 넣었다.
- **자기분석 기능 추가**: `check_accuracy.py`가 이제 단순히 적중/실패만 기록하는 게 아니라,
  그 예측에 실제로 쓰인 시즌승률/최근폼 데이터를 근거로 "왜 맞았는지/왜 틀렸는지"를 문장으로 만들어
  `accuracy_log.analysis_note`에 저장한다. 화면(어제/그저께 탭)에서 카드 안에 회색 박스로 표시됨.
- **날짜 선택을 오늘/어제/그저께 3개 탭으로 제한**했다 (달력 전체 대신). 어제/그저께 탭에서는
  실제 스코어 + 승패 적중/실패 뱃지 + 위 자기분석 코멘트가 함께 보인다.
- **오버/언더는 배트맨 실배당이 있을 때만 확률로 보여준다.** 배트맨 데이터가 없는 경기는
  자체 계산한 숫자를 그럴듯하게 보여주지 않고 "배트맨 라인 없음"이라고 정직하게 표시한다
  (내부적으로는 여전히 예측에 자체 계산 라인을 참고하지만, 화면에는 실제 배당 라인이 있을 때만 노출).
- **KBO는 이제 실제 사이트에서 진짜 데이터를 가져온다.** KBO 공식 사이트는 자바스크립트로
  나중에 표를 채우는 방식이라 `requests`로는 안 됐는데, Selenium을 써서 실제 브라우저처럼
  열고 기다렸다가 파싱하도록 바꿨다. 사용자가 실제로 캡처해준 화면 구조를 기반으로 만들어서
  실제 데이터(8/1~8/2 KBO 경기)로 파싱 테스트까지 완료함. **크롬 브라우저 설치 필요.**
- **오버/언더 확률 계산 버그 수정**: 배트맨 실배당이 없을 때, 화면에 보여주는 라인과
  확률 계산이 서로 다른 기준을 쓰고 있어서 숫자가 이상하게 나오던 문제를 고쳤다.
  이제 자체계산 시에는 항상 50% 근처의 정직한 숫자가 나온다 (우리 라인 자체가 우리 추정치이므로
  당연히 그 라인 기준으로는 오버/언더가 거의 반반이어야 맞다).
- **"어제" 탭이 비어있던 문제 해결**: 이 앱을 처음 쓰는 날에는 "어제" 경기 자체가 DB에
  없어서 계속 비어보였다. `update_yesterday_results.py`가 이제 어제 경기를 다시 수집하면서
  예측이 없는 경기는 사후적으로 예측까지 만들어준다 (완벽한 "사전 예측"은 아니고 오늘 기준
  팀 성적으로 계산되지만, 처음 켜는 날 어제 탭이 텅 비어보이는 것보다는 나음). 이후로는
  정상적으로 매일 예측 → 다음날 결과 확인 흐름이 이어짐.
- **화면(UI) 전면 재설계**: 타이포그래피 크기/굵기 일관성, 여백, 세그먼트 형태의 날짜/리그
  선택 버튼, 카드 디자인을 다시 다듬었다.
- **NPB(일본야구)도 이제 실제 데이터가 들어온다.** 공식 npb.jp의 일정 페이지(/scores/)는
  접속이 막혀있었지만(403), 대신 다른 공개 일정 사이트(sborisov.brinkster.net)로 오늘/어제/내일
  일정을 가져오도록 만들었다. 팀 순위(승/패/승률)는 npb.jp의 순위 페이지(/bis/eng/.../std_c.html,
  std_p.html)가 의외로 막혀있지 않아서 그대로 사용한다. 실제 데이터로 파싱 테스트 완료함.
  - **한계**: 일정 소스가 오늘/어제/내일만 지원해서 "그저께"는 NPB만 안 뜰 수 있음.
  - **한계**: 최종 스코어(결과)를 주는 소스를 아직 못 찾아서, NPB는 승패 적중여부 확인이 안 됨.
  - **한계**: 최근10경기 승률/평균득실 데이터가 없어서 그 부분은 "정보 없음"으로 뜸 (거짓 없이
    있는 데이터만 쓰는 원칙 유지 — 나중에 다른 소스를 찾으면 채울 수 있음).
- 다음 단계:
  1. 결과 검증 로직 (`accuracy_log`) — 다음날 실제 스코어와 예측 비교
  2. Electron 패키징 (진짜 "설치된 프로그램" 느낌 원할 경우)

```
sports-predictor/

│   ├── kbo_collector.py              # KBO 오늘 경기 수집 (스크래핑)
│   ├── kbo_team_stats_collector.py   # KBO 팀 시즌 승률/평균득실 수집 (스크래핑)
│   ├── npb_collector.py              # NPB 오늘 경기 수집 (스크래핑)
│   ├── npb_team_stats_collector.py   # NPB 팀 시즌 승률/평균득실 수집 (스크래핑)
│   ├── betman_odds_collector.py      # 배트맨(betman.co.kr) 오버/언더 실제 배당 라인 수집
│   └── team_name_map.py              # 배트맨 한글 팀명 ↔ DB 팀명(영문/일본어) 변환표
├── db/
│   ├── schema.sql
│   └── db.py                          # 연결/upsert/조회 헬퍼
├── features/
│   └── feature_builder.py             # DB 데이터를 예측용 피처로 조합
├── model/
│   └── predictor_v1.py                # 가중치 기반 예측 (승리확률 + 오버언더 + 등급)
├── run_predictions.py                 # 위 둘을 엮어서 하루치 예측을 predictions 테이블에 저장 (MLB/KBO/NPB 전부)
├── api/
│   └── server.py                      # FastAPI — GET /api/today?league=MLB|KBO|NPB
├── web/
│   └── index.html                     # 브라우저에서 여는 화면 (등급별 정렬, 색 구분 강화)
├── run_app.bat / run_app.command      # 더블클릭하면 서버 켜고 화면 자동으로 열림
├── daily_refresh.bat                  # 3개 리그 데이터 수집 + 예측 계산을 한 번에 실행 (윈도우)
├── setup_daily_task.bat               # 위 daily_refresh.bat을 매일 오전 8시 자동 실행되도록 등록 (윈도우 작업 스케줄러)
└── requirements.txt
```

## 전체 실행 순서

**1) 처음 한 번만 (패키지 설치)**
```bash
cd sports-predictor
pip install -r requirements.txt
```

**2) 매일 자동 갱신 설정 (윈도우, 한 번만 하면 됨)**
`setup_daily_task.bat`을 **관리자 권한으로 실행**(우클릭 → 관리자 권한으로 실행)하면, 매일 오전 8시에
`daily_refresh.bat`이 자동으로 실행되어 MLB/KBO/NPB 데이터를 갱신하고 예측을 다시 계산함.
시간을 바꾸고 싶으면 윈도우 "작업 스케줄러" 앱에서 "SportsPredictorDailyRefresh" 작업을 찾아 수정하면 됨.

수동으로 지금 바로 갱신하고 싶을 땐 `daily_refresh.bat`을 더블클릭하면 됨.

**3) 화면 보기**
- 윈도우: `run_app.bat` 더블클릭
- 맥: `run_app.command` 더블클릭
- 또는 수동으로: `python api/server.py` 실행 후 `web/index.html`을 브라우저로 열기

아이콘/독립 창까지 갖춘 "진짜 설치된 프로그램" 느낌은 Electron 패키징이 필요해서 별도로 요청 주시면 진행하겠습니다.
